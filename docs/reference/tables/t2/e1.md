# T2 / F3: E1 population fill divergence on DB data (2022)

RIVF'26 camera-ready, handoff task T2, item F3. This reruns E1 on data drawn from
the Algotrade DB. It does **not** edit `t4_measured_results.md`: the coordinator
merges these rows. Nothing was tuned toward the old numbers.

- **Old run:** the old local corpus (`hermes-parquet`, window 2021-02-05..2022-12-30;
  E1 used 2022 only). 385 tickers, 95,815 ticker-days, 477,537 decisions. Source:
  `figures/e1_fill_divergence.json` (left unchanged).
- **New run:** an Algotrade DB slice, extracted 2026-11-24.
  - Population: 391 tickers, 97,269 ticker-days, **484,949 decisions**, each
    judged under soft, hard and probabilistic.
  - Window: [2022-01-01, 2023-01-01). The first and last sessions are
    2022-01-04 and 2022-12-30.
  - Full tables: `e1_aggregates.md` / `e1_aggregates.json` (generated; this folder).
- **Selection rule (unchanged):** HSX `instrumenttype='stock'` tickers in the ticker
  master with ≥ 200 distinct `close` sessions in 2022. On the DB, this is
  `measurements/e1_regenerate.py::SELECTION_SQL`. The same rule re-run on the slice
  (`fill_divergence.discover_universe`) gives the identical 391 tickers; the run
  checks this.
- **Design (unchanged):** five on-grid intents per ticker-day: market buy, limit
  buy/sell at close, limit buy at floor, limit sell at ceiling. 1,000 shares each,
  10% participation cap, probabilistic seed 7 / `p_touch` 0.5. A question is
  skipped when its price is absent: 698 floor/ceiling-less ticker-days drop the two
  band intents.
- **CIs:** Wilson score 95% on every proportion. This assumes independent
  decisions; they are actually clustered by ticker-day and ticker, so the Wilson
  interval is narrower than it should be. For that reason the headline
  disagreement and the soft/hard quantity ratio also carry a **ticker-cluster
  percentile bootstrap** (2,000 reps, seed 20221).
- **Old CIs:** the old values below carry Wilson intervals recomputed from the
  counts in the old JSON (`n/a` where the old run published no count). Old and
  new are different populations, so overlapping CIs is not the test. The test is
  whether the old run's conclusions still hold.

## The checks that matter

- **The policies disagree materially.** On a realistic 2022 HSX order flow, 31.4% of
  decisions [ticker-cluster bootstrap 31.0, 31.8] have their outcome set by the
  fill policy, not the market. Soft executes 1.91× the quantity hard does.
  **Holds.**
- **The disagreement depends on the order intent.** Market orders diverge 95.4%:
  only soft fills them, and every other policy abstains. Limits at the close
  diverge about 23%. Deep passive limits diverge 9.2% (floor) and 5.5% (ceiling).
  These intervals are far apart, so **this holds**. The pinned test's bounds
  (market > 0.5, ceiling < 0.25, gap > 0.3) pass on the full population as well as
  on its 5-ticker subset.
- **What moved, and why:**
  - The band-edge rows fell about 0.5–0.75 points (floor 9.90 → 9.15, ceiling
    5.99 → 5.55). That is outside the old CIs, but it is not a property change.
  - The DB population is a different set of tickers and days (391 vs 385 tickers,
    +1,454 ticker-days). The DB ticker master holds only each ticker's *latest*
    exchange/type assignment, as did the old corpus's at an earlier date.
  - The DB's daily rows can also differ from the old dev extract.
  - The old ticker list was never saved (only counts), so the two universes
    cannot be diffed ticker by ticker. This was not assessed further.

## Reproduce

```
PY=.venv/bin/python
# needs DB access (credentials read at runtime by scripts/rivf26_extract.py)
PYTHONPATH=src $PY -m measurements.e1_regenerate all --data-dir <rivf26 data>/t2-e1
# statistics only, from an existing slice (no DB):
PYTHONPATH=src $PY -m measurements.e1_regenerate run --data-dir <rivf26 data>/t2-e1
# the pinned test against the slice (skipped when PLUTUS_DATA_ROOT is unset):
PLUTUS_DATA_ROOT=<rivf26 data>/t2-e1 PYTHONPATH=src $PY -m pytest strategies/test_e1_fill_divergence.py
```

`select` takes about 1 s, `extract` about 6 min (3,129 scoped queries) and `run`
about 9 s.

## Publication forms (owner decision pending)

The same `run` produces both. Nothing below the repo line is committed.

- **(a) Raw slice:** `rivf26/data/t2-e1/`. Nine daily parquet files (close, open,
  max, min, ceil, floor, reference, dailyvolume, ticker master) for the 391 tickers
  over 2022: 1,312,963 bytes (1.25 MiB) in total, under the size flag. Per-file
  sha256 values are in that directory's `DATA-MANIFEST.md`.
- **(b) Statistics only:**
  - Committed: `measurements/e1_regenerate.py` (script and selection rule), plus
    `docs/reference/tables/t2/e1_aggregates.{json,md}` (by-intent × by-policy
    disagreement, fill, indeterminate and quantity tables, N, Wilson CIs).
  - Not committed, kept in the data directory pending the owner's OK:
    `rivf26/data/t2-e1/e1_decisions.parquet`. It holds 1,454,847 rows (one per
    decision × policy) with columns `ticker, date, intent, policy, outcome,
    evidence, missing`, and **no price, volume or quantity column**. Quantity is
    left out because it is min(1,000, 10% of daily volume) and so leaks volume.
  - Known engine behaviour (brief item 4): `soft` labels every market-order fill's
    evidence `traded_through`. The outcomes are right; that label is not.
